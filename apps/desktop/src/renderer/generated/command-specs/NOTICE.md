# Command specs & generator modules

Generated by `scripts/generate-command-specs.cjs`. **Do not edit by hand** — run
`npm run generate:specs` to regenerate.

## `command-specs/*.json` — static structure

Slim subcommand/option/arg structure extracted from the **Fig autocomplete specs**
([github.com/withfig/autocomplete](https://github.com/withfig/autocomplete), **MIT**).
Args that carry a runnable generator are flagged `hasGenerator`; the generator
itself lives in the sibling module below.

## `command-spec-modules/*.js` — runnable generators

The full Fig spec for each command, bundled (esbuild) with its generator
**functions preserved** (`script` / `postProcess` / `custom` + local helpers), so
the renderer can run dynamic value completion (e.g. git branches, docker
containers). The `@fig/autocomplete-generators` helper imports are aliased to a
build-time stub (`scripts/fig-generators-stub.mjs`) — those prebuilt generators
(filepaths/ai/keyValue) are out of scope here. Source specs: withfig/autocomplete (**MIT**).

## Runtime

`src/renderer/lib/command-spec/fig-runtime.ts` executes these generators. It is
ported from **Amazon Q Developer CLI** (the open-source Fig successor), tag
`v1.6.0`, `packages/autocomplete/src/generators/` — **Apache-2.0 / MIT**. The only
substantive change is the `executeCommand` seam, which runs commands on the
connected remote host via our auxiliary channel instead of the local machine.
